Открытый **неофициальный клиент Telegram для HarmonyOS NEXT**, написанный на
ArkTS/ArkUI поверх [TDLib](https://core.telegram.org/tdlib) — библиотеки
Telegram, подключённой через нативный мост N-API.

## Возможности

- **Аккаунты** — вход по номеру телефона с 2FA, несколько аккаунтов,
  переключение и выход
- **Список чатов** — папки, архив, счётчики непрочитанного, состояние соединения
- **Сообщения** — форматированный текст, фото, альбомы, видео, файлы, стикеры
  (WEBP / TGS / WEBM), кастомные эмодзи, ответы, пересылка, реакции, ветки
  комментариев, закреплённые и отложенные сообщения, множественный выбор
- **Отправка** — автодополнение упоминаний и команд, медиа, файлы, голосовые,
  музыка, геопозиция, контакты, опросы, кубики
- **Звонки** — сквозное шифрование, аудио и видео 1:1 через tgcalls
- **Групповые звонки и трансляции** — многопользовательский звук, камера и
  демонстрация экрана, трансляции каналов, плавающее окно внутри приложения
- **Темы и истории** — списки тем форума с отдельными лентами сообщений;
  полноэкранный просмотр историй
- **Поиск** — глобальный поиск по 11 категориям
- **Профили** — пользователи, боты, группы и каналы; редактирование аватара,
  описания и имени пользователя; QR-визитка
- **Настройки** — приватность и безопасность, уведомления, хранилище, сеансы и
  устройства, папки чатов, энергосбережение, тёмная тема

## Структура

```
AppScope/            конфигурация приложения (имя пакета, иконка)
entry/src/main/ets/
  tdkit/             мост TDLib N-API, клиент, служба авторизации
  store/             неизменяемые store + подписки (чаты, сообщения, …)
  pages/             страницы ArkUI (вход, список чатов, чат, профиль, поиск …)
  services/          потоковое медиа, фоновые задачи трансляций, аудио
  util/              разбор и форматирование (текст, альбомы, даты …)
entry/src/main/cpp/  нативный мост (libentry.so → libtdjson.so / libtgcalls_ohos.so)
entry/src/test/      модульные тесты (scripts/run-local-tests.sh)
scripts/             сборка и загрузка TDLib/tgcalls, локальные проверки
```

## Сборка

### Требования

- **DevEco Studio 6.0+** со встроенным OpenHarmony SDK/NDK
- `curl` и `file` (уже есть в macOS/Linux)

### 1. Нативные библиотеки

TDLib и tgcalls поставляются как готовые библиотеки в `entry/libs/arm64-v8a/`
(~50 МБ, в репозиторий не коммитятся). `libentry.so` линкуется с обеими —
**без любой из них сборка останавливается** на ninja:
`missing and no known rule to make it`.

**Вариант A — скачать готовые (рекомендуется):**

```bash
bash scripts/fetch-libs.sh [tag]   # обе библиотеки из Releases этого репозитория
```

Без аргумента скрипт берёт последний релиз. Не возвращайтесь к «плавающему»
тегу `tdlib-latest`: его `libtdjson.so` обновляется, а `libtgcalls_ohos.so`
отстаёт от версионированных релизов.

**Вариант B — собрать из исходников (10–15 минут на современном Mac):**

```bash
# нужны clang (Xcode CLT), cmake, ninja, gperf, patchelf
export OHOS_NDK_HOME=/Applications/DevEco-Studio.app/Contents/sdk/default/openharmony
bash scripts/build-tdlib.sh
bash scripts/build-tgcalls-ohos.sh
```

`build-tdlib.sh` полностью оборачивает
[`ErBWs/tdlib-ohos-build`](https://github.com/ErBWs/tdlib-ohos-build):
кросс-компилирует OpenSSL (статически, `1_1_1w`) и TDLib (release **1.8.65**)
под arm64-v8a, заранее генерирует исходники TL-схемы TDLib на хосте
(обязательно при кросс-компиляции) и приводит SONAME к `libtdjson.so` через
`patchelf` — без этого шага нативный мост **молча** не загружается. Скрипт
идемпотентен, повторный запуск безопасен.

`build-tgcalls-ohos.sh` при первом запуске скачивает и собирает WebRTC, это
долго. Зафиксированные версии и границы возможностей — в
[`scripts/tgcalls/README.md`](scripts/tgcalls/README.md).

### 2. Учётные данные Telegram API

TDLib требует ваши собственные `api_id`/`api_hash` — в репозитории их нет.

1. Зарегистрируйте приложение на <https://my.telegram.org/apps>.
2. Скопируйте `entry/src/main/ets/tdkit/ApiCredentials.template.ets` в
   `ApiCredentials.ets` в той же папке.
3. Сгенерируйте упакованные константы и вставьте три выведенных значения:

   ```bash
   node scripts/gen-creds.mjs <api_id> <api_hash>
   ```

`ApiCredentials.ets` в gitignore — **никогда не коммитьте реальные ключи**; при
утечке немедленно отзовите и создайте новые. Упаковка — это обфускация, а не
шифрование: она лишь усложняет извлечение из установленного пакета.

### 3. Подпись

`signingConfigs` в `build-profile.json5` пуст. Откройте проект в DevEco Studio и
используйте **File > Project Structure > Signing Configs > Support HarmonyOS
Auto-Sign** (нужен аккаунт разработчика Huawei), чтобы создать локальный
отладочный сертификат. Никакие материалы подписи коммитить не нужно.

### 4. Сборка и запуск

Откройте проект в DevEco Studio и запустите на устройстве или эмуляторе
HarmonyOS NEXT, либо:

```bash
hvigorw assembleHap --no-daemon
```

Проверка перед коммитом:

```bash
./scripts/run-local-tests.sh    # должно вывести "LOCAL TESTS: PASS"
```

Скрипт сначала выполняет проверку i18n, затем модульные тесты: статическая
проверка, отвечающая за секунду, не должна ждать двухминутную сборку тестов.

## Локализация

Весь текст интерфейса хранится в ресурсах. Исходный язык (упрощённый китайский)
— `entry/src/main/resources/base/element/string.json`; переводы лежат в папках с
языковым квалификатором (`ru/element/string.json` и т. д.), формы множественного
числа — в `element/plural.json`. Система подбирает язык устройства и
откатывается к `base`.

**`$r()` или `str()`.** Всё, что рисует компонент, использует
`$r('app.string.x')`: это `Resource`, который ArkUI перечитывает при смене
конфигурации, поэтому переключение языка срабатывает сразу. `str('x')`
возвращает обычную строку, зафиксированную на этапе сборки, — только там, где
действительно нужен `string`: `@State` типа `string`, поля моделей, сравнения,
`.join()` и код вне UI. Если параметр `@Builder` вызывает конфликт типов,
расширьте его до `ResourceStr`, а не возвращайте вызов к `str()`.

**Константы уровня модуля не могут хранить текст.** Они вычисляются при первом
импорте, когда источник строк ещё не готов, и замораживают язык на этот момент.
Используйте функцию (`fallbackCountries()`, а не `FALLBACK_COUNTRIES`).

**Не сопоставляйте состояние по отображаемому тексту.** `label.substring(0, 2)`
или `text.includes('Повтор')` ломаются в момент смены языка — ветвитесь по
структурированным полям.

Диагностические строки, попадающие только в `console.*`, не переводятся;
помечайте их `// i18n-exempt: <причина>`.

```bash
node scripts/i18n-extract.mjs               # оставшийся жёстко зашитый текст
node scripts/i18n-extract.mjs --domain util # детали и предложения ключей
node scripts/i18n-lit.mjs <file>            # литералы с номерами строк
node scripts/i18n-check.mjs                 # проверка (входит в run-local-tests.sh)
```

`i18n-check.mjs` проверяет пять вещей: каждый ключ из кода есть в `base`; каждый
ключ из `base` где-то используется; **в значениях ресурсов не осталось
`${`-шаблонов, а нумерация подстановок совпадает между языками**; нет «сирот»
вне `base` и видно, каких записей не хватает каждому языку; **в уже покрытых
проверкой папках нет китайских литералов**.

Третий пункт добавили позже: проверка, тесты и компилятор видят по одному классу
ошибок, но никто из них не замечает, что значение `file_downloading` — это сам
исходник шаблона `${sizeLabel} · загрузка`. Такая ошибка проявляется только на
устройстве.

`MIGRATED` в `scripts/i18n-config.mjs` теперь охватывает все папки с исходниками
— новые папки нужно добавлять туда, иначе проверка молча их пропустит. Имена
ключей: `<домен>_<компонент>_<смысл>`, например `chat_forward_title`.

## Статус и оговорки

- В активной разработке; интерфейс ориентируется на официальный клиент Android.
- Это **неофициальный** клиент. Используйте свои учётные данные API и соблюдайте
  [условия Telegram API](https://core.telegram.org/api/terms).
- Поиск незнакомых пользователей подчиняется серверным правилам видимости
  Telegram/TDLib: обычно находятся только пользователи с публичным именем или
  иным образом попавшие в область поиска; перебирать произвольные номера
  телефонов так нельзя.
